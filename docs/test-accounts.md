# 테스트 계정 안내

플랫폼을 실제로 로그인해서 둘러보기 위한 계정 목록과 동작 전제를 정리한 문서입니다.

## 공통 비밀번호

```
CarbonLedger!2024
```

비밀번호를 공개해 둔 이유는 단순합니다. 비밀로 유지해야 하는 계정은 테스트 계정이 아닙니다.
이 비밀번호는 아래 "데모 모드"에서만 통용되며, Supabase를 연결하면 앱은 이 비밀번호 검사 코드를
아예 실행하지 않습니다.

## 계정 목록

`supabase/seed.sql` 이 `public.users` 에 넣는 다섯 행과 동일한 ID·이메일·이름·역할입니다.
데모 모드로 둘러본 화면과 Supabase에 시드를 적용한 뒤 둘러본 화면이 같은 사람을 보여주도록
일부러 일치시켰습니다.

| 이메일 | 이름 | 역할 | 보유 권한 |
| --- | --- | --- | --- |
| `admin@hankook-mfg.co.kr` | 김관리 | 회사 관리자 (`company_admin`) | 조회·작성·승인·관리·내보내기 |
| `site-admin@hankook-mfg.co.kr` | 이현장 | 사업장 관리자 (`site_admin`) | 조회·작성·승인·내보내기 |
| `reviewer@hankook-mfg.co.kr` | 박검토 | 검토자 (`reviewer`) | 조회·승인·내보내기 |
| `auditor@hankook-mfg.co.kr` | 정감사 | 감사인 (`auditor`) | 조회·감사·내보내기 |
| `viewer@hankook-mfg.co.kr` | 최열람 | 조회자 (`viewer`) | 조회 |

## 로그인 방법

1. `/login` 으로 이동합니다.
2. 화면 아래 **테스트 계정** 카드에서 원하는 계정의 `이 계정으로 로그인` 을 누릅니다.
   자격증명을 직접 확인하고 싶으면 `입력란에 채우기` 를 눌러 값이 채워지는 것을 본 뒤
   `로그인` 을 누르십시오.
3. `/settings` → **내 계정과 권한** 카드에서 지금 로그인한 계정의 역할과 권한 목록을
   확인할 수 있습니다.
4. 로그아웃은 우측 상단 아바타 메뉴 또는 `/settings` 의 `로그아웃` 버튼입니다.

## 역할별로 무엇이 달라지는지

역할을 바꿔 로그인하면 다음이 실제로 달라집니다. 화면이 달라지는 것을 확인하는 것이
이 계정들의 목적입니다.

- **좌측 메뉴 구성** — `조회자` 로 로그인하면 결재/승인, 공급업체, 배출계수, 설정, 감사이력이
  메뉴에서 사라집니다. `감사인` 은 감사이력을 유지하되 결재/승인을 잃습니다.
  근거는 `src/lib/navigation.ts` 의 `ROLE_NAV_KEYS` 이며, 각 컷의 이유가 주석에 있습니다.
- **결재 조치 버튼** — `/approvals` 의 승인·반려·재작성요청 버튼은 `can_approve` 를 가진
  역할에만 나타납니다. 버튼 유무는 서버 액션이 사용할 인가 함수를 그대로 호출해 결정하므로,
  눌렀을 때 거부되는 버튼은 처음부터 그려지지 않습니다.
- **공급망 조치 버튼** — `/suppliers` 의 승인·반려·재요청도 동일한 방식입니다.
- **전자서명 귀속** — 결재 조치 시 서명에 기록되는 사람이 로그인한 계정으로 바뀝니다.

메뉴에서 링크를 숨기는 것은 편의이며 통제가 아닙니다. 각 서버 액션은 요청마다 역할과
테넌트를 다시 검사합니다. 숨겨진 링크는 잠긴 문이 아니기 때문입니다.

## 동작 전제 (중요)

앱은 Supabase 설정 여부에 따라 **서로 다른 두 경로**로 로그인합니다. 어느 경로가 동작 중인지는
`/login` 화면 상단의 안내 문구에 표시됩니다.

### 1) 로컬 데모 모드 — Supabase 공개 변수 2개가 모두 없거나 빈 경우

- `NODE_ENV`가 `production`이 아닌 로컬 개발에서는 데모 모드가 기본 활성화됩니다.
  `ENABLE_DEMO_MODE=false`로 명시하면 로컬에서도 끌 수 있습니다.
- 위 다섯 계정과 공통 비밀번호로 로그인됩니다. 별도 준비가 필요 없습니다.
- 세션은 HMAC 서명된 쿠키(`cl_demo_session`)로 유지됩니다. 쿠키에는 사용자 ID와 만료시각만
  담기고, 역할·이름·회사는 서버가 카탈로그에서 조회합니다. 따라서 쿠키를 변조해 권한을
  올릴 수는 없습니다.
- **이것은 실제 인증이 아닙니다.** 비밀번호가 저장소에 공개되어 있으므로 신원 증명 효과는
  없습니다. 역할별 권한 확인과 제품 미리보기에만 사용하십시오.
- 로그인하지 않아도 화면은 열립니다. 이때는 `site_admin` 상당의 서버 고정 체험 운영자로
  동작하며 화면에 그 사실이 표시됩니다. 데모 계정으로 로그인하면 선택한 역할이 우선합니다.
- 로컬 기본값을 벗어나 데모 모드를 명시적으로 켤 때는 `DEMO_SESSION_SECRET`을 32바이트 이상의
  무작위 값으로 설정하십시오. 결재·공급망 조치 결과는 서버 메모리에만 남아 재시작 시 초기화됩니다.

### 2) 운영 인증 미구성 모드 — 안전 차단

- `NODE_ENV=production`에서 Supabase 공개 변수 2개가 모두 없으면 기본값은 `disabled`입니다.
  공개 테스트 비밀번호와 고정 체험 운영자는 활성화되지 않으며 보호 경로는 `/login`으로 이동합니다.
- 두 Supabase 공개 변수 중 하나만 설정한 부분 구성도 오류를 감추기 위해 `disabled`로 차단됩니다.
- 외부 데모 배포가 꼭 필요한 경우에만 `ENABLE_DEMO_MODE=true`와 강한 `DEMO_SESSION_SECRET`을
  명시하십시오. 실제 운영 데이터가 있는 배포에서는 사용하지 마십시오.

### 3) Supabase 연결 모드 — `NEXT_PUBLIC_SUPABASE_URL` 과 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 가 있는 경우

- 로그인은 `supabase.auth.signInWithPassword` 로 처리됩니다. 데모 경로는 완전히 비활성화되며
  `cl_demo_session` 쿠키는 읽히지도 않습니다.
- 위 계정으로 로그인하려면 **먼저** 인증 사용자 행을 만들어야 합니다:

  ```bash
  psql "$DATABASE_URL" -f supabase/migrations/0001_initial_schema.sql   # 최초 1회
  # ... 0002 ~ 0005 순서대로
  psql "$DATABASE_URL" -f supabase/seed.sql
  psql "$DATABASE_URL" -f supabase/seed-auth-users.sql
  ```

  `supabase db reset` 을 쓰는 경우 seed.sql 은 자동 적용되지만
  `seed-auth-users.sql` 은 자동 적용되지 않습니다. `auth` 스키마에 쓰는 파일이므로
  로컬 Postgres 컨테이너에는 적용하면 안 되기 때문에 분리해 두었습니다.

- `seed-auth-users.sql` 은 JWT 클레임 세 개를 함께 넣습니다: `company_id`, `role`, `full_name`.
  `company_id` 가 없으면 액터가 null 로 해석되어 모든 조치가 거부되고, `role` 이 없으면
  가장 낮은 권한인 `viewer` 로 떨어집니다.
- 로그인하지 않은 요청은 `src/proxy.ts` 가 `/login` 으로 보냅니다.

## 인터넷에 노출되는 환경에 올릴 때

공개 주소에 올리기 전에 인증 모드를 명시적으로 정하십시오.

- 실제 운영은 Supabase 공개 변수 2개를 모두 설정하고 `ENABLE_DEMO_MODE`를 `false` 또는 미설정으로
  유지합니다. 둘 중 한 변수만 둔 부분 구성은 의도적으로 차단됩니다.
- 제한된 제품 시연에만 운영 데모를 사용하고, 이때 `ENABLE_DEMO_MODE=true`와 강한
  `DEMO_SESSION_SECRET`을 설정합니다. 공개 비밀번호이므로 신원 인증 수단으로 취급하면 안 됩니다.
- Supabase에 `seed-auth-users.sql`을 적용했다면 공개 전 해당 `auth.users` 행을 삭제·비활성화하거나
  무작위 비밀번호로 교체합니다. 소스의 `TEST_ACCOUNT_PASSWORD`를 운영 비밀번호 저장소로 사용하지
  마십시오.

운영 환경에서 단지 Supabase 변수를 빼는 것으로 데모 모드가 켜지지는 않습니다. 이 안전 차단을
우회하지 말고 실제 Supabase Auth, 이메일 확인, MFA 정책을 구성하십시오.
